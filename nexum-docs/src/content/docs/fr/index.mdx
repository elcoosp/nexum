`nexum` donne aux applications Rust une façon unique et cohérente de gérer les schémas d'URL personnalisés. Vous déclarez les schémas que votre application possède, nexum les enregistre auprès du système d'exploitation, et votre code reçoit chaque événement de lien profond — que l'URL vienne d'un navigateur, d'un second processus ou de la ligne de commande — via un seul canal producteur-consommateur.

L'espace de travail est organisé pour que vous ne dépendiez que de ce dont vous avez besoin : [`nexum-core`](/reference/core/) contient les primitives indépendantes du framework, [`nexum-platform`](/reference/platform/) effectue l'enregistrement au niveau OS, et de minces crates d'adaptateur exposent le tout à travers les idiomes de cinq frameworks UI.

## L'écosystème en un coup d'œil

| Crate                                         | Objet                                                                                   |
| --------------------------------------------- | --------------------------------------------------------------------------------------- |
| [`nexum`](/reference/nexum/)                  | Façade : cœur + plateforme + l'attribut de bootstrap `#[deep_link]` en une seule dépendance |
| [`nexum-core`](/reference/core/)              | Producteur `DeepLinkHub` et consommateur `DeepLinkHandle` — bloquant, asynchrone, flux, borné |
| [`nexum-platform`](/reference/platform/)      | Enregistrement OS, transfert mono-instance, validation plist, entrée mobile             |
| [`nexum-macros`](/reference/macros/)          | L'attribut `#[deep_link(schemes = ["myapp"])]`                                          |
| [`nexum-floem`](/reference/adapters/floem/)   | Adaptateur Floem renvoyant un `ReadSignal<Option<String>>` réactif                      |
| [`nexum-xilem`](/reference/adapters/xilem/)   | Adaptateur Xilem avec le wrapper de vue `with_deep_links`                               |
| [`nexum-dioxus`](/reference/adapters/dioxus/) | Adaptateur Dioxus avec un chemin de lancement en un appel `launch_desktop`              |
| [`nexum-leptos`](/reference/adapters/leptos/) | Adaptateur Leptos renvoyant `RwSignal<Option<String>>`, prêt pour wasm                  |
| [`nexum-gpui`](/reference/adapters/gpui/)     | Adaptateur GPUI pour les applications style Zed                                         |

## Support des plateformes

| Plateforme        | Méthode d'enregistrement                  | Détection à l'exécution           |
| ----------------- | ----------------------------------------- | --------------------------------- |
| **Windows**       | Registre (par utilisateur)                | Arguments CLI                     |
| **macOS**         | `Info.plist` (validateur inclus)          | Apple Events (`GURL` via `objc2`) |
| **Linux**         | Fichier `.desktop` + `xdg-mime`           | Arguments CLI                     |
| **Android / iOS** | Déclaratif (générateurs manifest / plist) | Colle de framework → `mobile::push_*` |
