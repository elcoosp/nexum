Mobile platforms have no API nexum can call to register a scheme — both Android and iOS declare schemes statically in app metadata. Nexum therefore ships **generators** for those declarations plus small intake functions your framework glue calls when the OS hands over a URL.

## Declare the schemes

**Android** — `nexum_platform::mobile::android_manifest_intent_filter` renders a complete `<intent-filter>` (VIEW action, `DEFAULT` + `BROWSABLE` categories, one `<data android:scheme="...">` per configured scheme). Paste it into the activity in your `AndroidManifest.xml`:

<Code lang="rust" code={`let config = Config::builder().scheme("myapp").build().expect("valid config");
let filter_xml = nexum_platform::mobile::android_manifest_intent_filter(&config);`} />

Generated shape:

<Code lang="xml" code={`<intent-filter>
 <action android:name="android.intent.action.VIEW" />
 <category android:name="android.intent.category.DEFAULT" />
 <category android:name="android.intent.category.BROWSABLE" />
 <data android:scheme="myapp" />
</intent-filter>`} />

**iOS** — use `nexum_platform::plist::url_types_xml` to render the `CFBundleURLTypes` block for your app's `Info.plist`, exactly as on desktop macOS. `plist::missing_schemes` lets you verify the built plist against a `Config` in a test.

## Feed runtime URLs into the hub

Initialize the global hub once at startup — for example by storing a hub with `set_hub` — then call the intake function for your platform from the framework glue that receives OS callbacks:

| Platform | Callback you wire | Intake function |
| --- | --- | --- |
| Android | `onCreate` / `onNewIntent` (`Intent.getDataString()`) | `nexum_platform::mobile::push_intent_url(url)` |
| iOS | `openURLContexts(_:)` / `open URL:` delegate | `nexum_platform::mobile::push_open_urls(urls)` |

Both push into the global hub as `Source::System` and return `Err(Error::HubNotSet)` if the hub was never initialized, so a wiring mistake fails loudly at first use:

<Code lang="rust" code={`// Android JNI glue (pseudo-call):
nexum_platform::mobile::push_intent_url(intent_data_string)?;

// iOS delegate (pseudo-call):
nexum_platform::mobile::push_open_urls(url_strings)?;`} />

<Aside type="danger">
The intake functions are target-gated: `push_intent_url` compiles only on `target_os = "android"` and `push_open_urls` only on `target_os = "ios"`. Gate your glue code with the same cfg attributes. CI type-checks the platform crate against real Android and iOS targets so this cannot silently rot.
</Aside>

## Consumption stays unchanged

Everything downstream of the hub is identical to desktop: your adapter signal, `DeepLinkHandle` consumer, bounded-queue policy, and event parsing work the same, because mobile events differ only in how they *enter* the hub.
