`nexum-dioxus` integrates deep links into Dioxus desktop applications. Besides the usual core and platform re-exports, it re-exports `dioxus::LaunchBuilder` and the desktop config types (`dioxus_desktop::Config` as `DesktopConfig`, `LogicalSize`, `WindowBuilder`) so a deep-link app needs no extra imports for launching.

## API

| Item | Signature | Description |
| --- | --- | --- |
| `setup` | `fn setup(config: &Config) -> Result<()>` | Registers and stores the handle globally; `HubAlreadySet` on double init |
| `handle` | `fn handle() -> &'static DeepLinkHandle` | Stored handle; **panics** before `setup` |
| `use_deep_link` | `fn use_deep_link() -> Signal<Option<String>>` | Hook returning a signal that updates on every URL; **panics** before `setup` |
| `with_deep_link_handler` | `fn with_deep_link_handler(config: DesktopConfig) -> DesktopConfig` | Attaches a custom event handler that feeds tao's `Event::Opened` URLs into the hub |
| `launch_desktop` | `fn launch_desktop(config: &Config, desktop_config: DesktopConfig, app: fn() -> Element)` | One-call path: setup + handler + launch |

## The one-call path

```rust
let nexum_config = Config::builder().scheme("myapp").build().expect("valid config");

let desktop_config = DesktopConfig::new()
    .with_window(WindowBuilder::new().with_title("Deep Link Demo"));

launch_desktop(&nexum_config, desktop_config, app);
```

`launch_desktop` runs `setup` (**panicking** on failure with `nexum-dioxus: deep-link setup failed`), wraps the desktop config with `with_deep_link_handler`, and launches through `LaunchBuilder`. Note the `app` parameter is a plain function pointer `fn() -> Element`.

## The hook

```rust
#[component]
fn App() -> Element {
    let deep_link = use_deep_link();
    rsx! {
        p { "Last deep link: {deep_link:?}" }
    }
}
```

The signal starts as `None` and is replaced by each arriving URL. A `use_future` internally awaits `handle.recv()` and writes into the signal.

## Event wiring and cold start

`with_deep_link_handler` pattern-matches tao's `Event::Opened` and pushes each URL into the hub with `nexum_platform::push_url`. Two behaviors follow from that design:

- URLs arriving through tao events are delivered as `Source::System`.
- Push errors are deliberately ignored (`.ok()`): after hub shutdown the event stream stops contributing.
- Cold starts on Windows and Linux still arrive via the command-line relay inside `setup` — before your components render — so the hook can already hold the launch URL on first paint.

> [!CAUTION]
> The adapter pins `tao 0.34.8` to match `dioxus-desktop`'s requirement; both crates must see the identical event enum. Cargo resolves this automatically when versions align — do not override tao in your own manifest.
